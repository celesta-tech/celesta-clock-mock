# CLS-5177 — {D} [clock-mock] Close open Dependabot alert: phpunit upgrade and new tag

Sub-task: https://celesta.atlassian.net/browse/CLS-5177 · Parent: https://celesta.atlassian.net/browse/CLS-4972 · Repository: celesta-clock-mock

## Overview

`composer.json` pins the dev dependency `phpunit/phpunit` to exactly `9.5.4`. Dependabot alert #1 ([GHSA-vvj3-c3rp-c85p](https://github.com/advisories/GHSA-vvj3-c3rp-c85p), high, "Unsafe Deserialization in PHPT Code Coverage Handling") affects `>= 9.0.0, < 9.6.33`, and it is the only open alert in this repository. Dependabot's own security update for it failed on 2026-11-11 (`update_files` error), so no pull request exists.

This sub-task raises the pin to `9.6.39`, the latest release of the 9.6 line, which still supports PHP `>=7.3`. It then confirms that the existing test suite passes. The new release tag is set by the lead after the merge, as the parent requires. No library code changes.

## Architecture & Design

- Only the `require-dev` section of `composer.json` changes. The library's runtime requirements (`php >=7.4.0`, `ext-uopz >=6.1.1`) and everything under `src/` are untouched, so consumers see no runtime change.
- The exact-pin style of `require-dev` is kept (`mockery/mockery` `1.4.3`, `phpunit/phpunit` `9.6.39`). The repository commits no `composer.lock` (it is in `.gitignore`), so the exact pin is the only thing that makes installs reproducible.
- `.github/workflows/test.yml` is not changed. It targets the retired `ubuntu-20.04` runner and reports no checks on pull requests. Verification therefore runs locally in Docker, and the output goes into the pull request.

## Implementation Tasks

1. In `composer.json`, under `require-dev`, change `"phpunit/phpunit": "9.5.4"` to `"phpunit/phpunit": "9.6.39"`. Change nothing else in the file.
2. Run the existing test suite in Docker on PHP 7.4 with `uopz`, using the command under Testing Strategy, and confirm that it passes and that phpunit `9.6.39` is installed.
3. Add the test command's summary (the PHPUnit version line and the final `OK (…)` line) to the pull request description as the verification record.

## Testing Strategy

No new tests. The change is a dev-tool version bump, and the existing suite (`tests/ClockMockTest.php`, configured by `phpunit.xml.dist`) is what has to keep passing.

The repository has no `CLAUDE.md`, no Makefile and no container. Run the suite in a throwaway `php:7.4-cli` container, never with PHP on the host:

```bash
docker run --rm -v "$PWD":/app -w /app php:7.4-cli bash -c '
  apt-get update -qq && apt-get install -y -qq git unzip >/dev/null &&
  pecl install uopz-6.1.2 >/dev/null && docker-php-ext-enable uopz &&
  curl -sS https://getcomposer.org/installer | php -- --install-dir=/usr/local/bin --filename=composer >/dev/null &&
  composer update --no-interaction --no-progress &&
  vendor/bin/phpunit -c .'
```

Expected output: `PHPUnit 9.6.39` in the header and a final `OK (<n> tests, <m> assertions)`, with every test from the `master` run still present.

Manual verification after the merge, by the lead: Dependabot alert #1 shows as fixed (repository → Security → Dependabot).

## Proteus tests

None. celesta-clock-mock is a dev-only library with no deployed service, so no Proteus suite can observe it. The parent's Proteus criterion applies to the services, not to this library. The criterion "the existing test suite passes" is covered by the local run above.

## Edge Cases & Error Handling

- **phpunit 9.6 deprecation output.** `phpunit.xml.dist` references the 9.3 schema. If 9.6 prints a configuration-schema or deprecation warning but the suite still reports `OK`, leave it: migrating the configuration is not part of this task. A failing or erroring test is a stop. Report it, and do not change `src/` or the tests to make it pass.
- **Dependency resolution.** If `composer update` cannot resolve `phpunit/phpunit 9.6.39` together with `mockery/mockery 1.4.3` on PHP 7.4, stop and report the conflict. Do not loosen other pins.
- **Files left by the container.** `vendor/` and `composer.lock` created by the Docker run are ignored by git and must not be committed.

## Acceptance criteria

- `composer.json` requires `phpunit/phpunit` `9.6.39`, outside the vulnerable range `>= 9.0.0, < 9.6.33`. After the merge to `master`, Dependabot alert #1 closes as fixed.
- No other dependency moves to a new major version. `mockery/mockery` stays at `1.4.3`, and `php` / `ext-uopz` stay as they are.
- The existing suite in `tests/` passes on PHP 7.4 with `uopz`, with phpunit `9.6.39` installed.
- The diff touches only `composer.json`: no change under `src/` or `stubs/`, so the library's behaviour is unchanged.
- A new release tag carrying the fix is set after the merge. The lead sets it, and it is not part of this branch.
